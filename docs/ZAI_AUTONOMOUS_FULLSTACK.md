## 3. The staged anchored-generation method (what actually worked)

Measured capability boundary of the frozen model on this machine:

- ~15-line anchored completions: reliably solvable with bounded sampled
  bursts (logic passed on the first burst sample; greedy was trapped in
  a repetition loop).
- ~50-line whole modules: 32 consecutive failures (best 7/24; most
  syntactically invalid). Whole-module generation is **beyond** the
  model.
- ~5–15-line staged pieces with per-piece check-gated acceptance:
  near-deterministic success.

The staged builders decompose each module at contract boundaries:

1. **Anchors**: the prompt ends with the exact public-contract signature
   (`function createStore(filePath) {`, a route registration, a React
   hook block), so the base model continues with code, not prose.
2. **Per-piece specs with exact shapes**: worked input→output examples
   (the Session-031 lesson, re-verified here) plus literal code shapes
   for the smallest pieces.
3. **Check-gated acceptance**: a piece is accepted only when ITS OWN
   evaluator checks pass in a trial assembly (siblings stubbed), plus
   structural gates (code-only keyword matching to reject spec-echo;
   state-shadowing rejection; persistence probe that constructs the
   store against a pre-written file). No fallback accepts.
4. **Deterministic extraction**: model bytes are cut at disclosed
   boundaries (method definition, JSX start, balanced-brace depth) —
   never rewritten.
5. **Resumability**: every accepted piece checkpoints; the build
   survives arbitrary interruption (essential on a 2-CPU machine).

## 4. Execution-guided repair (mission sections 7 and 12)

The real browser test found two bugs the module-level evaluator could
not see (both repaired through the model, never hand-edited):

1. `addProject` parsed the POST response (`{project}`) instead of
   refetching the list — the project list emptied after creation.
   Repaired by re-bursting the piece with the browser feedback injected
   into the prompt; offline checks stayed 13/13.
2. CSS `.project-btn { display: none; }` made project buttons invisible
   (selector-presence checks passed; visibility is a browser property).
   Repaired with browser feedback in the repair prompt; 22/22 checks,
   no `display:none` rules remain.

Both repairs are recorded in the repair-memory dataset with full
structured fields (requirement, failed/repaired excerpts, principle,
category, `detected_by: real Playwright browser test`).

## 6. Independent transfer: ClinicQueue (mission section 11)

Frozen second-application contract (different domain and terminology:
appointments/patients/departments/urgency; synthetic data only), private
tests frozen in `archagent/clinic_contract.py` before any transfer run.
Comparison: whole-module generations, 3 seeds × 2 conditions × 2 roles,
TaskFlow repair-memory concepts retrieved into the prompt (concepts
only, no TaskFlow code):

| Condition | logic | store |
|---|---|---|
| baseline | 0/3 | 6/16 |
| with patterns | 1/3 | 0/0 |

**Conclusion: no measurable transfer.** The retrieved TaskFlow concepts
(refetch-after-mutation, element visibility) are domain-specific and do
not address the actual bottleneck, which is the model's inability to
produce valid whole modules in unfamiliar domains without staging.
In-context pattern memory as implemented here does not generalize. This
is a temporary-in-context mechanism only; nothing touched the weights.

## 7. Weight-space findings (mission section 10)

1. **Corrected prior evidence first** (mission section 3): the Session
   010 joint factor set was re-evaluated at the intended ≤1.5% bound
   after the scaling bug fix — the edit is **behaviorally inert**
   (identical accuracy, zero task flips on dev/val/holdout). The
   historical dev/val gains were an artifact of the cap-violating
   reload. All fix tooling + tests are in this branch
   (`tests/test_archcircuits_corrections.py`, 14 protocol tests).
2. **New causal probe on the real repair pattern**:
   `experiments/zai-taskflow/weight_space_probe.py` measures whether any
   layer causally carries the refetch-vs-parse distinction (the exact
   bug the browser caught). Result: the model prefers the buggy
   continuation by 4.6 logits (quantifying why the bug arises), but the
   mediation scan shows **no clean mid-layer site** — the largest effect
   (L0/mlp +1.48) is superficial token-identity, with everything else
   < 0.15 nats. The pattern is distributed, not localized.
3. **Decision**: no bounded weight edit is applied. Per the mission's
   own bar — an edit is successful only if it improves independent
   execution-tested behavior — and given (a) the corrected inertness of
   bounded edits where localization previously succeeded, and (b) no
   localization candidate here, constructing an edit would be unjustified
   curve-fitting. The 6-way comparison of mission section 10 collapses
   to the conditions that exist: untouched vs untouched+retrieval vs
   untouched+execution-guided-staging (measured above).

- Model: `ARCHAGENT_MODEL_DIR` / `ARCHCIRCUITS_MODEL_DIR` env (no
  machine-specific defaults; architecture verified on load; SHA-256 in
  report repro blocks).
- Evaluator: `archagent/worker.js` (Node vm realms, module allowlists,

  127.0.0.1, synthetic data only).
- Protocol tests: `python -m pytest tests/test_archagent.py
  tests/test_archcircuits_corrections.py` — 34 tests, all passing.
- CI: `.github/workflows/session033-zai-autonomous-fullstack.yml`
  (workflow_dispatch: protocol-tests / corrections / holdout).

## 9. Limitations

- The application is simple by production standards; the CSS is
  functional but plain (the model's own aesthetics).
- The jsdom UI evaluator checks offline-demo behavior; online behavior
  is verified by the real browser test only (which is how the two real
  bugs were found).
- Transfer and weight-space conclusions are from small-N measurements
  bounded by a 2-CPU budget; they are honest negatives, not proofs of
  impossibility.
- The `put_project` route was added after holdout run 1 revealed its
  absence (a public-contract coverage gap); both holdout runs are
  recorded and disclosed.
- Logic contract v1 (6-key) was simplified to v2 (4-key) before any
  logic module passed, after 88 recorded failed attempts; v1 attempts
  are archived in the generations log.

## 10. Recommended next experiments

1. Stage-aware transfer: does the STAGED builder (scaffold, not
   patterns) transfer to ClinicQueue? The scaffold is
   contract-parameterized and might — but that measures infrastructure
   reuse, not model learning.
2. Larger contrastive sets for the refetch-vs-parse probe (N>1 pairs)
   before concluding the pattern is unlocalizable.
3. A holdout-clean second application built with the staged method to
   measure whether the method's success rate holds across domains.
4. Browser-in-the-loop acceptance for online-mode UI behavior (the
   current loop only feeds browser failures back after integration).
